# 待办池（细节级）

> 每条都写成「场景 → 现状 → 期望 → 成本」，方便直接开工。
> 成本：S（半天）/ M（1-2 天）/ L（3 天+）

## A · 单实例体验

### A1 开服前预检（Preflight）
- 场景：点「启动」后 3 秒闪退，用户不知道哪错了
- 现状：只有进程退出码，控制台里是一屏 Java 报错
- 期望：启动前跑一遍检查（Java 版本 ≥ 需求、端口被占用、EULA 未接受、内存 > 物理内存、磁盘 < 2G、Mod 依赖缺失），逐条给「为什么 + 一键修」
- 成本：M

### A2 控制台
- 场景：服开了，玩家问「卡不卡」，服主要现查
- 现状：能看日志、能发指令，但没有补全、没有常用指令、错误行不显眼
- 期望：`Tab` 补全玩家名与指令；常用指令（list/tps/say/save-all/whitelist）一键；ERROR 行左侧色条 + 点击展开堆栈；日志导出
- 成本：M

### A3 玩家
- 场景：想踢人 / 加白名单，得记指令
- 现状：靠 `op`/`whitelist` 指令 + 读 json，在线列表只有名字
- 期望：在线玩家卡片（延迟、维度、坐标可选）、一键踢/封/传送、白名单批量导入、封禁列表管理
- 成本：M

### A4 世界与备份
- 场景：手滑删了存档 / 想回到昨晚
- 现状：只列数据包，没有备份
- 期望：一键备份（zip + 时间戳 + 大小）、保留 N 份、恢复前自动再备份一次、世界目录直达、显示各维度占用
- 成本：M

### A5 Mod
- 场景：装完 Mod 起不来，不知道谁冲突
- 现状：列表 + 客户端比对
- 期望：启停（`.disabled`）、更新检查（Modrinth）、依赖缺失提示、`config/` 快捷定位、重复 Mod 检测
- 成本：M

### A6 配置
- 场景：只想改个 MOTD / 难度
- 现状：表单 + 源码，但没有校验、没有说明
- 期望：每个键一句人话说明；非法值即时提示；常见组合预设（小服/生电/竞技）；改完提示「需重启」
- 成本：S-M

## B · 开玩链路

### B1 进服包导出
- 场景：朋友要进服，版本、Mod 对不上
- 期望：导出 `.mrpack`（版本 + 客户端 Mod + 说明）；或 zip 含 mods + servers.dat + 图文步骤
- 成本：M

### B2 启动器探测
- 场景：用户已经有 PCL2/HMCL，不想再装一个
- 期望：扫描常见路径与注册表，列出「检测到的启动器」，显示版本与游戏目录
- 成本：S

### B3 启动器联动
- 场景：点一下就能进游戏
- 现状：无
- 期望：优先命令行唤起；不支持则写入其实例目录（版本隔离）后提示点一次
- 成本：L（每家启动器要单独适配验证）

### B4 内置启动器（可插拔）
- 场景：用户机器上什么启动器都没有
- 期望：模块化安装/卸载；离线登录可用；微软登录后置
- 成本：L

## C · 联机

### C1 地址分享卡片
- 场景：把地址发给朋友
- 期望：一张卡片（地址、版本、需要的 Mod、房间口令）一键复制成一段话
- 成本：S

### C2 局域网一键开
- 场景：同一 WiFi 下就不用穿透
- 期望：检测本机内网 IP + 端口，给 `192.168.x.x:25565` 直连地址
- 成本：S

### C3 FRP 体验
- 场景：第一次配 frp 不知道填什么
- 期望：预设模板（常见公共 frps）、连通性测试、失败原因翻译
- 成本：M
