# v28 修订审计：网页版实测问题与全项目排查

> 2026-11-01 · v28 修订版。已推送 `main`、部署 Pages，并替换 GitHub Release 资产。
>
> 这一轮从三个实测致命问题出发：网页端点「选择」没有反应、第一次打开没有引导装助手、助手会弹窗口。
> 修完之后又按「屎山性 + 漏洞」做了一遍排查，下面把根因、修复、还没解决的问题分开写清楚。

## 1. 实测问题的根因

### 1.1 网页端点「选择」没有反应

这不是一个按钮的问题，是三处断链叠在一起：

| 层 | 问题 | 结果 |
|---|---|---|
| 来源白名单 | 助手只放行 `https://wulons.github.io`，实际页面在 `https://incoruptus.github.io` | 所有请求 403 |
| 配对 | 页面没有令牌时不会向助手换令牌，只有深链 `?t=` 一条路 | 直接打开网页时全部 401 |
| 目录选择 | 网页版调用 `dialog:open-directory`，助手用 PowerShell 弹系统对话框 | 对话框可能落在浏览器后面，看起来就是「点不动」 |

修复方式：

- 来源白名单改为 `https://incoruptus.github.io`，并删除不属于当前仓库的 `wulons.github.io`。
- 新增 `POST /api/pair`，只对白名单来源返回配对令牌；网页第一次打开会自动配对，令牌失效会自动重配。
- 网页版不再调用系统对话框，改成页面内的文件浏览器：磁盘、常用位置、面包屑、上一级、手动路径、文件过滤都由 `fs:list` / `fs:drives` 提供。
- 桌面版仍用原生对话框，`pickPath()` 是唯一入口，所有「选择…」按钮都走它。
- 第二轮复查又抓到 5 个绕开 `pickPath()` 的入口：模组页 `.minecraft` 目录、新建服务器安装目录、从客户端开服目录、控制台导出日志、邀请导出进服包。桌面端这 5 处走原生对话框，网页端会退回 PowerShell 对话框。现已全部统一，并在 `check-release` 增加源码守卫：除 `path-picker.ts` 外再出现 `mcss.dialog.` 就直接失败。

### 1.2 第一次打开没有引导装助手

根因有两个：

- 助手新建配置时把 `setupComplete` 写成了 `true`，首次向导被直接判定为「已经完成」。
- 模式选择的「先浏览界面」也会把 `setupComplete` 设成 `true`，之后不再出现向导。

修复方式：

- 助手默认配置改为 `setupComplete: false`，与桌面版一致。
- 网页版首次向导新增第一步「装助手」：说明网页为什么读不到硬盘、下载安装包、检测连接；连上后自动进入「怎么玩」。
- 助手连上后重新读取配置，避免页面启动时 `config.read` 失败、后面新建实例把本机已有实例覆盖。
- 离线期间用户选过的模式、完成过的引导会保留，不会被一次重读抹掉。

### 1.3 助手会弹窗口

根因：Rust 默认按控制台子系统编译，启动时会出现一个黑框；子进程（java、curl、tar、reg、powershell）也没有统一隐藏。

修复方式：

- `#![cfg_attr(target_os = "windows", windows_subsystem = "windows")]`，按 GUI 子系统编译。
- 统一用 `quiet_cmd()` 启动控制台程序，带 `CREATE_NO_WINDOW`；java 服务端、curl、tar、reg、powershell 都不再分配窗口。
- 去掉 `println!` / `eprintln!`，日志写到 `%APPDATA%\wulons-mcss\agent.log`，2 MB 轮转。
- 安装包开始菜单只保留「打开开服茶」「启动助手（后台）」「卸载」；没有托盘、没有窗口。
- 开机自启默认勾选，写 HKCU Run；网页「设置 → 本机助手」可以直接开关。

### 1.4 旧标签页与旧助手不会被误判

另一台电脑上可能同时存在两层旧东西：16:40 打开的旧标签页，和没有 `/api/pair` 的旧助手。两者都会让「选择」看起来没反应。

- 页面构建写 `version.json`；打开着的页面每 60 秒、切回前台、从 bfcache 恢复时检查一次，发现新构建就提示「页面有新版本 / 刷新」。
- 离线提示条和目录选择器的错误态都提供「刷新页面」。
- 助手 `/api/health` 返回 `pair: true`；页面发现健康接口没有这个能力，就明确提示「助手是旧版本，请重新运行最新的 mcss-agent-setup.exe」。
- 日志写入加互斥锁，多个配对请求同时进来不会把日志写成交错的乱码。
- 安装器把「启动助手」从 postinstall 移到普通 `[Run]`：静默安装也会把助手拉起来，不会出现装完网页仍显示「未启动」。
- 助手改用 `panic = "unwind"`，并安装 panic hook：坏 jar/异常请求只影响当前线程，panic 内容写进 `agent.log`，不再让整个后台进程退出。

## 2. 安全排查

### 2.1 已修复

| 编号 | 问题 | 处理 |
|---|---|---|
| H1 | `Origin: null` 被当成合法来源。任意网页可以用沙箱 iframe 拿到令牌。 | `null` 一律 403，只有空 Origin（本机进程）放行。 |
| H2 | 白名单包含 `wulons.github.io`，那个站点不属于当前仓库。 | 删除，只保留 `incoruptus.github.io` 和本机来源。 |
| H3 | 日志会打印带 `t=<token>` 的深链。 | 日志统一 `redact()`，令牌显示为 `***`。 |
| H4 | 用 `cmd /c start` 打开 URL，URL 里的 `%`、`&`、引号会被 cmd 二次解释。 | 改用 `rundll32 url.dll,FileProtocolHandler`，参数不再经过 shell。 |
| H5 | 深链房间码直接拼进 URL，可注入引号/命令。 | `url_component()` 对房间码做百分号编码。 |
| H6 | 深链把令牌放在 `#` 后，前端只读 `?` 查询，令牌实际丢失。 | 新增 `extractAgentToken()`，同时读 search 和 hash；有单测。 |
| H7 | 网页版打开时可能读不到配置，之后新建实例会用空列表覆盖本机实例。 | 助手连上后重新 `config.read`，并保留离线期间的选择。 |
| H8 | 助手只认端口，不认已有实例，自启动和手动双击可能冲突。 | 端口被占用时先探 `/api/health`，已有实例就直接退出。 |

### 2.2 仍然存在的风险

- **GitHub Pages 共享来源**：`incoruptus.github.io` 下所有项目共用同一个 Origin，也就共用 localStorage 里的令牌。同账号下任何一个仓库被注入，都能控制本机助手。这是项目站点无法按路径隔离 Origin 带来的限制；换独立域名可以缓解。
- **自动配对放宽了信任边界**：以前必须把带令牌的深链交给用户，现在白名单来源可以主动换令牌。好处是第一次打开就能用，代价是白名单来源本身必须可信。
- **令牌生成不是密码学随机**：`gen_token()` 用时间戳和 PID 混合，不是 CSPRNG。本机文件权限是主要边界；后续可以换成系统随机源。
- **安装/升级会结束助手进程**：`[Code] PrepareToInstall` 在覆盖同一目录时执行 `taskkill`。如果当时有 Minecraft 服务端在跑，java 进程可能变成孤儿。卸载同理。后续应在结束前检查 `server:status` 并提示。
- **没有代码签名**：安装包和 exe 未签名，SmartScreen 可能提示「未知发布者」。
- **浏览器兼容性**：依赖 Chrome/Edge 的 Private Network Access；Firefox / Safari 访问本机助手的行为没有真机验证。

## 3. 代码质量排查

### 3.1 已处理

- 所有网页版路径选择集中到 `pickPath()`，不再有散落的 `window.mcss.dialog.*`。
- 新增 `fs:drives`、`app:autostart`、`app:autostart-set` 三个通道，preload / agent / httpClient / api 类型四处同步，parity 仍为 100%。
- `scripts/web-e2e.cjs` 从 16 项扩到 24 项，覆盖配对、来源拒绝、磁盘、自启、GUI 子系统。
- `scripts/web-shot.cjs` 增加 `WEB_NO_TOKEN` / `WEB_NO_AGENT` / `MCSS_ACT`，可以真机验证自动配对和页面内选择器。
- `vite.web.config.mts` 增加 `envDir`，本地构建能读到仓库根目录的 `.env.local`。
- 测试从 208 增加到 211，新增深链令牌解析的 3 个单测。
- 文档里的测试数、agent 体积、部署地址、校验值同步到当前结果。

### 3.2 还没处理

- `agent/src/main.rs` 约 4800 行，HTTP、配置、下载、服务端、备份、Mod、联机、对话框全在一个文件。功能稳定，但继续加功能前应该拆模块。
- 配置默认值在 `agent/src/main.rs`、`electron/ipc/config.js`、`src/renderer/lib/config-model.ts` 各有一份。字段已经对齐，但仍然是三处维护。
- `app.pickJava` 没有调用方；`dialog.*` 现在只在 `path-picker.ts` 的 Electron 分支使用，网页端不再落到 agent 的 PowerShell 对话框。agent 里的系统对话框实现仍保留用于 parity 和旧调用，属于可删除的备用路径。
- 桌面版和助手共用同一份 `%APPDATA%\wulons-mcss\config.json`，两边同时运行没有跨进程文件锁。
- `package-win.js` 仍硬编码输出目录和 rcedit 路径；只适合当前开发机，不适合作为通用构建脚本。
- 旧版 `docs/V28-AUDIT.md` 是历史审计，没有回填这一轮的 211 个测试；以本文件为准。
