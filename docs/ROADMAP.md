# Wulon's MCSS · 产品路线（v27 之后）

> 2026-10-28 起。定位从「服务器管理器」调整为 **开服 + 开玩**：
> 在本地把服开起来，让朋友用最少的步骤进到游戏里。

## 一句话

**低成本、方便快捷、丝滑地和好朋友一起玩 MC。**

衡量指标只有一条：**从「我想和朋友玩」到「朋友在游戏里」要几分钟、几次点击。**

## 判断标准（用来砍需求）

| 问题 | 不通过就砍 |
|------|-----------|
| 这一步能让玩家更快进服吗？ | 不能 → 放到二级入口或删掉 |
| 这是「单实例日常」需要，还是「一次性配置」？ | 一次性 → 收进向导/高级设置 |
| 出错时用户能不能自己看懂并修好？ | 不能 → 加预检/自愈/一键修复 |
| 默认值能不能直接开玩？ | 不能 → 改默认值，别让用户选 |

## 能力地图

业界参照：MCSManager 走「分布式面板 + 多实例 + 文件管理 + 定时任务」，
Prism / PCL2 / HMCL 走「多实例隔离 + 一键启动 + 资源下载」。
MCSS 的位置不是再做一个面板，而是 **本机、单人、开服即玩** 的那一层。

### 主轴：单实例的灵便管理

不做多实例的堆叠，先把一个实例做到顺手：

| 域 | 要做到的 |
|----|---------|
| 生命周期 | 启动/停止/重启/强杀；开服前预检（Java 版本、端口占用、EULA、内存、磁盘、Mod 依赖）；失败给可操作的原因 |
| 控制台 | 实时分级、搜索、指令历史与补全、常用指令一键、错误行高亮、复制/导出 |
| 玩家 | 在线列表（延迟/维度）、OP/白名单/封禁、踢人/传送、最近登录 |
| 世界 | 存档大小与维度清单、手动/定时备份、回滚、world 目录直达 |
| Mod | 启停（.disabled）、更新检查、依赖/版本冲突提示、config 快捷编辑 |
| 配置 | server.properties 智能表单 + 校验 + 说明；JVM 预设；端口占用提示 |
| 联机 | FRP（已通）、局域网一键开、地址分享卡片（含版本与 Mod 要求） |
| 观测 | CPU/内存/磁盘、TPS/MSPT、玩家数趋势 |

### 三条「开玩」路径（按成本从低到高）

1. **进服包**：把「版本 + 加载器 + 客户端 Mod 清单 + 地址 + 说明」打成 `.mrpack` / zip，
   朋友用任意启动器导入即可。零侵入、跨启动器通用。
2. **启动器联动**：检测本机 PCL2 / HMCL / 官方 / Modrinth / Prism，
   能命令行唤起就唤起，不能就写好实例目录再提示点一次「启动」。
3. **内置启动器（兜底）**：当用户没有启动器时，MCSS 自己拉起客户端。
   插件化、可热插拔；先做离线登录，微软登录后置。

## 分期

| 阶段 | 内容 | 交付判据 |
|------|------|---------|
| A | 开服前预检 + 单实例各域细节打磨 | 启动失败率下降，控制台/玩家/世界不再「有入口没细节」 |
| B | 进服包导出 + 启动器探测 | 朋友拿到一个文件就能进服 |
| C | 启动器联动（命令行/实例目录） | 点一下，游戏窗口起来 |
| D | 内置启动器插件 | 没有任何启动器也能玩 |

## 工程约定

- 每个改动都要能回答「这让谁更快进服」；
- UI 三问：**该不该出现 / 还能多给什么 / 有没有更优解**；
- 每轮结束：`pnpm typecheck` + `pnpm test` + `pnpm build` + 截图自检；
- 需求进 `docs/BACKLOG.md`，带「场景 / 现状 / 期望 / 成本」四栏。
