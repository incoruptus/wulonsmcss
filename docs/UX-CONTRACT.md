# UX 契约：每块界面都要能回答三个问题

> 背景：v28 修「网络体检」时发现，页面只给了体检结论，没有告诉用户「接下来做什么」。
> 这类问题可能反复出现，所以这里落一条可复用的界面契约，避免同类问题继续出现。

## 1. 三问契约

每个页面、每张状态卡、每个空状态，至少要回答：

1. **这是什么 / 我现在在哪？** —— 标题 + 一句人话说明，不假设用户懂术语。
2. **现在是什么状态？** —— 用「已验证 / 未知 / 不通」这类结论，不用裸指标。
3. **我下一步做什么？** —— 一个明确动作，最好再给一个备用出口。

只做第 2 步、不做第 3 步，产品就停在体检阶段，没有形成闭环。

## 1.1 先假设用户是谁

这五类人都是目标用户，不按「懂网络的人」设计默认路径：

1. 从未玩过 MC，一时兴起想和朋友一起玩
2. 玩过 MC，但不知道怎么做多人联机
3. 想开服，但不知道怎么配置
4. 想和朋友一起玩之前的单人存档
5. 被朋友叫来联机，但根本没接触过 MC

因此：

- 不假设用户有公网 IP、会端口映射、懂 NAT / UPnP / IPv6 / frp。
- 不假设用户使用校园网、家庭宽带或某种特定网络；只描述「当前网络允许什么」。
- 不假设用户已经安装 Minecraft；第一次来的玩家要知道先装游戏、再粘贴邀请。
- 技术细节放进「技术详情」折叠区，主路径只保留人话和动作。

## 2. 冗余设计

同一个目标至少给两条路：

| 场景 | 主路径 | 备用路径 |
|---|---|---|
| 联机 | 复制可用地址发给朋友 | 开隧道 / 换网络 / 诊断码 |
| 空世界 | 新建世界 | 导入现有数据包 / 修复旧包 |
| 空玩家 | 去联机页拿地址 | 启动服务器 / 配置隧道 |
| 搜索无结果 | 清空搜索 | 换英文名 / 换分类 |
| 配置读不到 | 重试 | 打开目录 / 看日志 |
| 加入失败 | 复制诊断码 | 进服包 / 手动检查客户端 |

冗余指同一目标有不同可行动作；单纯重复文案没有价值。

## 3. 文案规则

新增/改写文案必须遵守：

- 不用「雷霆小短句」堆砌；一个意思写成完整句子。
- 前后逻辑连贯，结论在前，原因和动作在后。
- 不用「不是…是…」「不是…而是…」「并非…而是…」这类否定—转折句式。
- 破折号只用于必要的补充，不拿它连接两个短句。
- 不写「不会动你的文件」「不会锁死」这类此地无银的自我辩解；直接说程序行为。
- 技术名词第一次出现时，用一句人话解释，或者给一个「这是什么」的提示。

## 3.1 错误态

错误信息至少包含「哪里出错 + 用户能做什么」：

| 场景 | 不这样写 | 改成 |
|---|---|---|
| AI 回复没内容 | JSON 数据中缺少 changes 字段 | AI 回复里没有配置改动，请让它按提示词格式重新生成 |
| 服务端缺启动文件 | 缺少 server.jar / fabric-server-launch.jar | 服务端目录里缺少启动文件，请在服务器设置里重新安装 |
| 诊断码损坏 | Trailing junk found after the end of the stream | 诊断码内容损坏，可能复制时遗漏了部分字符 |
| 配置项不存在 | 不属于有效的 server.properties 配置项 | 服务器没有这个配置项 |

## 5. 组件约束

- 状态结论 + 动作统一用 `Callout`（`src/renderer/components/ui/callout.tsx`），不要每处手写一套。
- 卡片标题用 `SectionHead` 时必须带 `desc`；没有 `desc` 的卡片要么是纯数据，要么补说明。
- `EmptyState` 必须带 `action`；确实没有动作时，说明为什么没有。
- 地址类文本必须可复制；复制按钮不能只给房间码，直连地址也要给。
- 技术状态旁必须有人话结论，例如「对称 NAT」旁边写「直连基本不通，建议走隧道」。

## 6. 下一轮检查方式

1. 每页截图，按三问逐卡检查。
2. 每个空状态、错误状态、加载状态都点一遍。
3. 对「只有状态没有动作」的卡片，补 `Callout` 或 `EmptyState action`。
4. 新增文案跑一遍第 3 节规则；发现否定—转折句式就重写。

## 7. 已知功能缺口

- **单人存档导入**：已补「用现有客户端开服 → 把单人存档一起带过来」；原存档保留，自动清 `session.lock`，目标已有 world 时拒绝覆盖。
- **第一次玩 MC**：加入页已经有「先安装 Java 版、再粘贴邀请」的折叠说明；安装包/账号流程仍需要更完整的引导。
- **语言入口**：i18n 框架已就绪，页面迁移和语言选择留到下一轮。
