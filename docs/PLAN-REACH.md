# 联机契约 · 实施计划（2026-10-30）

> 目标不是「再加一个联机功能」，而是把「朋友能不能进来」变成产品里**可验证、可解释、可携带**的一件事。
> 这份计划只写范围和验收，不写营销话术。

## 1. 问题

现在的链路是：服主开服 → 去「联机」页配隧道 → 手抄一个地址 → 塞进邀请。
每一步都要求服主先懂网络。产品对「外面到底通没通」没有任何判断，
所以朋友说「连不上」时，双方都只能猜。

## 2. 目标（一条闭环）

```
开服 → 自动体检 → 邀请里带多条候选地址 → 玩家端自动竞速选最快 → 进服
                          ↘ 失败时生成诊断码 → 服主粘贴还原现场
```

验收只看三件事：

1. 服主开服后 10 秒内，界面上有一句明确的「朋友现在能不能进」。
2. 邀请里至少有「同 WiFi / 公网 / 隧道」三条候选，玩家端自动选，不问 IP。
3. 朋友进不去时，能带回来一段可复现的信息，而不是一句「连不上」。

## 3. 不做什么

- **不做 WebRTC / TURN / 信令**：我们已经有服务器，P2P 是给「没有服务器」的人用的。
  引入信令 = 引入滥用、配额、运维三类风险。
- **不做浏览器版 MC（Eaglercraft）**：版本停在 1.8/1.12，和「服务器管理器」定位冲突。
- **不做公开广场 / 语音 / 签到**：社区明确抵制，且偏离主线。
- **不伪造状态**：没验证就显示「未知」，不显示「已就绪」。

## 4. 四线同构

| | 服主 | 玩家 |
|---|---|---|
| **桌面** | 开服即体检；邀请自动选路；反向对齐客户端 | 加入页竞速；诊断码；进服包 |
| **网页** | 同一套 UI（agent 提供本机探测） | 无 agent 时退回第三方外证 + 进服包 |

- 所有判定逻辑进 `src/renderer/lib/reach.ts`（纯函数，带测试），UI 只做展示。
- 所有 IO 进 `src/renderer/lib/reach-io.ts`，桌面/网页共用 `window.mcss` 契约。
- 状态词只有四个：`已验证可达` / `仅本机` / `未知` / `离线`。玩家与服主用同一套词。

## 5. 阶段

### P1 · 可达性闭环（本轮）

| 交付 | 说明 |
|---|---|
| `reach.ts` | 地址合并/去重/排序、竞速、结论（纯函数） |
| `reach-io.ts` | 本机 SLP、公网 IPv4/IPv6、第三方外证、隧道地址 |
| 开服即体检 | 服务端 `Done` 后自动跑一次，卡片 + 一次性提示 |
| 邀请多地址 | `RoomDescriptor` 增加可选 `addrs[]`，`addr` 保留兼容 |
| 加入页竞速 | 并行探测所有候选，选最快；无 agent 时用外证兜底 |

验收：桌面与网页都能看到同一张「可达性」卡片；老房间码（无 `addrs`）仍能进。

### P2 · 网络体检后端

| 交付 | 说明 |
|---|---|
| `net:doctor` | IPv6 全球地址、STUN（公网 endpoint / NAT 类型）、UPnP 网关 |
| UPnP 映射 | 显式同意后开端口，带撤销；失败要说清是「路由器不支持」还是「运营商封入站」 |
| 防火墙 | 检测 + 引导放行（UAC），不静默改系统 |

桌面（Node）与 agent（Rust std）各一份实现，`check-parity` 必须 100%。

### P3 · 双向对齐 + 诊断码

| 交付 | 说明 |
|---|---|
| 反向对齐 | 服务端 → 客户端：只加不删、先备份、可撤销；跨启动器仍走 `.mrpack` |
| 诊断码 | 玩家端把版本/Java/Mod diff/探测结果压成一段码；服主粘贴即还原 |
| 依赖补全 | Modrinth 依赖链自动补齐（缺前置是「进不去」的常见原因） |

### P4 · 收口

- `check-release` 标记、`docs/FEATURE-MAP.md`、`PROJECT.md` 数字
- 桌面 + 网页截图各一组
- 打包、启动、真机验收

## 6. 协议演进

`RoomDescriptor` 保持 `v: 1`，只做**加法**：

```ts
addrs?: { k: "lan" | "ipv6" | "public" | "tunnel"; host: string; port: number }[];
java?: number; // 26.1+ = 25
```

- 旧客户端读新码：忽略未知字段，`addr` 仍可用。
- 新客户端读旧码：没有 `addrs` 时退回 `lan` + `addr`。
- 不换前缀，不破坏已经发出去的链接。

## 7. 已拍板 / 待确认

已按最保守的默认做掉：

1. **UPnP 默认关**：只在用户点「开直连」时改路由器，且给撤销入口。
2. **外证默认开**：卡片注明「来自一次外部回连」；探测失败显示「未知」，不判服务器死刑。
3. **反向对齐只加不覆盖**：同名文件不动；版本冲突只提示，跨启动器走进服包。

待确认（P2 前）：

- 隧道供应商抽象要不要一起做（playit.gg / Sakura API），还是 P2 先只做「本地直连体检 + UPnP」？
