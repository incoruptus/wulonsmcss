# 两种模式 × 单实例核心（UX 重构方案）

> 一句话：**产品的主体是"一个服务器"，不是"一堆实例"。**
> 服主与玩家是两种完全不同的入口，但共用同一套内核。

---

## 0. 现在的问题（先承认）

1. **IA 以"多实例管理"为骨架，却也没做好**：侧栏一级是「概览 / 实例 / 资源库 / 联机 / 加入房间 / 设置」，
   实例只是其中一页；而"当前在管哪一个"这个最重要的上下文，藏在 `activeInstanceId` 里，界面上没有存在感。
2. **资源库是全局的**：安装 Mod 时不问装到哪个实例，装完也不回写"这个实例已装"。
   结果就是——装完不知道装哪去了。
3. **只有 mod 没有 plugin**：服务端核心只有 vanilla / fabric，水桶服（Paper）用户直接出局（见 `SERVER-TYPES.md`）。
4. **玩家线是"一个页面"，不是"一种模式"**：玩家打开看到的是服主的导航（实例、资源库、联机），
   真正需要的"我要进朋友的世界"被挤到第五个位置。

---

## 1. 结论：**两种模式，一套内核**

| | 服主模式 | 玩家模式 |
|---|---|---|
| 回答的问题 | "我这台服现在怎么样、下一步做什么" | "我能不能进、还差什么" |
| 首页 | 实例仪表盘（状态 + 四宫格） | 加入房间（大输入框 + 我的服务器） |
| 导航主体 | 当前实例的六个面 | 加入 / 我的服务器 / 我的客户端 |
| 默认平台 | 桌面版 | 网页版 |
| 共享内核 | 房间码、SLP 探测、下载器、Java 探测、mrpack、客户端准备 | 同左 |

**模式是"预设"，不是"权限"**——玩家模式里也能"自己也开一个服"，服主模式里也能"加入别人的房间"。
只是默认把哪个摆在你面前。这样既不分裂产品，也不逼用户选边。

**为什么不做成两个应用/两套代码**：网页版与本地版必须一模一样（不可妥协的卖点），
再拆成两套模式代码，等于把一个不可妥协的点变成两个。一套内核 + 两套导航/首页，是唯一可行的拆法。

---

## 2. 四个核心对象

```
Instance（服务器）   服主的：目录 / 核心类型 / 版本 / 内存 / 端口 / 自动化
ClientProfile（客户端） 玩家的：版本 / 加载器 / mods / 资源包 / Java
SavedServer（收藏）   玩家的：名称 / 地址 / 版本 / 来源房间码 / 上次进入
Room（房间码）        两边共用：地址 / 局域网 / 版本 / 加载器 / Mod 指纹
```

关系：
- `Room` 由 `Instance` 生成，被 `SavedServer` 与 `ClientProfile` 消费。
- `ClientProfile` 可以**额外**装服主没有的 Mod（音效包、光影、小地图）——这是玩家侧的自由，不影响进服。
- `Instance` 的 `serverType` 决定 `contentKind = plugin | mod`，进而决定"内容"页长什么样、资源库查哪个源。

## 3. 服主模式

### 3.1 骨架

```
┌ 实例切换器 ─────────────────────────────────────────────┐
│  MCServer · 26.1 Paper · ● 已停止        [切换 ▾] [＋]  │
└─────────────────────────────────────────────────────────┘
   总览      控制台      内容      世界      玩家      联机      设置
─────────────────────────────────────────────────────────
   ＋ 新建服务器     导入现有服务器
   资源库（安装到当前实例）        偏好设置
```

- **实例切换器是常驻的一级元素**，不是侧栏里的一段列表。换实例 = 换整个工作区。
- 顶部六项全部是"当前实例的某个面"，不再是全局页面。
- 「联机」从全局降为实例的一个面（端口/穿透/房间码本来就属于某个服）。

### 3.2 首页（按你的草图）

```
┌ MCServer ── 26.1 · Paper ── D:\...\MCServer ────────────────┐
│ ● 已停止    运行时长 —   在线玩家 —   内存 —   端口 25565    │
│                                    [打开目录] [设置] [启动] │
└─────────────────────────────────────────────────────────────┘
┌ 性能 ───────────────┐ ┌ 邀请与快速配置联机 ──────────────┐
│ 内存 / 最近卡顿      │ │ 房间码 · 局域网 · 穿透状态        │
└─────────────────────┘ │ 「朋友需要装什么」 一句话         │
┌ 快捷方式 ───────────┐ └──────────────────────────────────┘
│ 备份 / 时间机 / 重启 │ ┌ 最近日志 ────────────────────────┐
│ 配置 / 打开目录      │ │ 最近 8 行 · 跳转控制台            │
└─────────────────────┘ └──────────────────────────────────┘
```

四宫格的每一格都必须**能点进去做事**，不做纯展示：

| 格 | 内容 | 动作 |
|---|---|---|
| 性能 | 内存占用、最近卡顿记录、上次崩溃 | 跳「控制台 · 卡顿」 |
| 邀请与联机 | 房间码（一键复制）、局域网地址、穿透状态 | 生成邀请 / 开穿透 |
| 最近日志 | 最近 8 行，错误高亮 | 跳「控制台」 |
| 快捷方式 | 备份、时间机、重启、配置、打开目录 | 直接执行 |

### 3.3 「内容」页 = Mod 或 插件

标签随 `serverType` 变：
- Paper / Purpur → 「插件」，目录 `plugins/`，数据源 Modrinth(plugin) + Hangar
- Fabric / Forge / NeoForge → 「模组」，目录 `mods/`，数据源 Modrinth(mod)
- Vanilla → 「数据包」+ 提示"原版不能装插件/模组，要不要换 Paper？"

这句提示很重要：**它是从原版服升级到水桶服的自然入口**，不是广告。

## 4. 玩家模式

```
┌ 加入 ───────────────────────────────────────────────────┐
│  [ 粘贴房间码 / 链接 / 地址:端口 ]         [体检并加入]  │
│  上次：朋友的创造服 · play.example.com:25565             │
└─────────────────────────────────────────────────────────┘
┌ 我的服务器（收藏，不是"游戏大厅"）───────────────────────┐
│ 朋友的创造服   26.1 Fabric   3 人在线    [进入] [删除]   │
│ 自己开的小服   26.1 Paper   离线        [进入]           │
└─────────────────────────────────────────────────────────┘
┌ 我的客户端 ──────────────────────────────────────────────┐
│ 1.21.4 Fabric · 12 个 Mod（含 3 个服主没装的自选 Mod）   │
│ [体检] [补全依赖] [导出进服包]                           │
└─────────────────────────────────────────────────────────┘
```

关键取舍：

- **不做"游戏大厅"**。大厅意味着"内容目录 / 服务器市场"，我们没有这个货源，做了就是空壳。
  改叫**「我的服务器」**：你保存过的、去过的，就这些。
  （若将来要做发现页，那是"社区/推荐"，与"我的"分开，别混在一个词里。）
- 玩家模式默认**不出现**"实例/控制台/资源库"这些词。
- 玩家模式里保留一个低调入口：「我也想开个服」→ 切到服主模式。
- 「我的客户端」是本轮新概念：玩家有**自己的**版本与 Mod，可以比服主多装东西（音效、光影、小地图）。
  进服前只做一件事：告诉我们**能不能进**；不能进，就给出"点一下就好"的补全。

## 5. 单实例核心怎么落地

1. **顶部实例切换器**：显示 `名称 · 版本 · 核心 · 状态`，点开是实例列表 + 「新建」+「导入」。
2. **路由改成实例内**：`/instances/:id/{overview,console,content,worlds,players,network,settings}`。
   没选实例时（或在玩家模式）不渲染服主导航。
3. **所有写操作带实例 id**：资源库安装、备份、快照、Mod 绑定，全部显式传 `instanceId`——
   顺手修掉"装完不知道装哪了"。
4. **资源库实例化**（本轮重点之一）：

```
安装到  [ MCServer · 26.1 Paper ▾ ]        ← 默认当前实例，可切
[搜索插件…]  筛选：[✔ 与本服兼容] [已安装]
┌────────────────────────────────────────────┐
│ EssentialsX 5.x    插件     ✔ 已装 v5.2     │
│ WorldEdit 7.x      插件     ＋ 安装          │
│ WorldEdit 7.2(旧)  插件     ⚠ 已有不同版本   │
└────────────────────────────────────────────┘
```

已装判断：读 `plugins/` 或 `mods/` 的实际文件名 + jar 元数据（现有 `mods.scan` 已经能做），
与 Modrinth 的 project/version 对不上时退化为"按文件名匹配"。

5. **兼容性**：筛选项默认按当前实例的 `mcVersion` + `serverType` 过滤；
   装不兼容的版本时给红字而不是静默失败。

## 6. 数据模型 v28

```ts
// config
version: 28
mode: "host" | "player"          // 上次所在模式
hostModeSeen: boolean            // 是否已经问过"你想干嘛"

instances: Instance[]            // 不变，但新增 serverType
interface Instance {
  serverType: "vanilla" | "fabric" | "forge" | "neoforge" | "paper" | "purpur";
  // loader 字段保留为兼容别名，读时映射
}

// 玩家侧（新增）
clientProfiles: ClientProfile[]
interface ClientProfile {
  id: string; name: string;
  mcVersion: string; loader: "vanilla" | "fabric" | "forge" | "neoforge";
  dir: string;                  // 客户端目录（默认 .minecraft）
  extraMods: { file: string; name?: string }[];  // 玩家自选、服主没有的
}

savedServers: SavedServer[]
interface SavedServer {
  id: string; name: string; address: string; port?: number;
  mcVersion?: string; loader?: string;
  fromRoom?: string;            // 房间码来源
  lastJoinedAt?: number;
  note?: string;
}
```

**迁移（v27 → v28）**：
- `loader: "fabric" | "vanilla"` → `serverType` 同名映射。
- `mode` 默认：桌面 `host`，网页 `player`（用户切过就以用户为准）。
- 新数组为空即可；不做破坏性重写，老实例一个不丢。
- 迁移必须有测试（现有 `config.test` 之外要补一条"v27 配置能读成 v28"）。

## 7. 旧页面 → 新位置

| 现在 | 之后 |
|---|---|
| 概览（多实例总览） | 服主首页 = 当前实例仪表盘 |
| 实例列表 | 切换器里的列表 + 「新建/导入」 |
| 实例详情 · 控制台/世界/玩家/设置 | 原样，成为一级面 |
| 实例详情 · Mod | 「内容」（按核心类型显示 插件/模组/数据包）|
| 资源库（全局） | 资源库（带目标实例 + 已装状态）|
| 联机（全局 FRP） | 实例的「联机」面 + 首页邀请格 |
| 加入房间 | 玩家模式首页 |
| 设置 | 偏好设置（全局）|

## 8. 验收（每条都能截图/探针验）

1. 首次启动问一次"你要开服还是玩"，之后不再问；侧栏可随时切。
2. 切换实例后，六个页面的数据全部跟着变（不是只有标题变）。
3. 资源库安装时明确显示"装到哪个实例"，装完立即显示"✔ 已装"，且 `plugins/` 或 `mods/` 里真有文件。
4. 原版实例的「内容」页给出"换 Paper"入口；Paper 实例不出现 `mods/` 相关 UI。
5. 玩家模式首页三步内能完成"粘贴码 → 体检 → 进服"。
6. 网页版与桌面版同一套（`check-parity` 100%）。
7. `scripts/ui-probe.cjs` 扫全部页面：无 console-error、无黑屏。

## 9. 分期（建议）

| 阶段 | 内容 | 为什么这个顺序 |
|---|---|---|
| **P1 骨架** | 数据模型 v28 + 迁移 + 模式切换 + 实例切换器 + 路由 | 一切 UX 都建立在"当前实例"这个上下文上 |
| **P2 服主首页** | 仪表盘 + 四宫格（按草图） | 你说的"首页应该是这样" |
| **P3 内容与资源库** | 内容页分流 + 资源库实例化 + 已装状态 | 修掉"装完不知道装哪" |
| **P4 玩家首页** | 加入 + 我的服务器 + 我的客户端 | 玩家线优先，但依赖 P1 的数据模型 |
| **P5 核心谱系** | Paper / Purpur provider（安装 + 启动 + 探测 + 导入） | 后端工作量最大，单独一轮 |

P5 与 P3 有强耦合（插件服才谈得上"插件"），如果想让 P3 真的可验证，P5 至少要做到 Paper 能装能起。
