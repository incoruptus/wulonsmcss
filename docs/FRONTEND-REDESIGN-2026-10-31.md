## 3. 改造前的关键问题

接手时项目功能完整，但体验层存在明显摩擦：

### 视觉与结构

- 页面里大量同权重小卡片，重要状态和次要信息混在一起。
- 两套总览并存：全局总览与实例总览指标重叠、布局不一致。
- 侧栏、标题栏、页面头部、总览里重复显示服务器状态。
- 标题、正文和限宽卡片有时不在同一条垂直线上。
- 大量 11–12px 次级文字，在深色主题下偏灰、偏弱。
- 卡片常用“灰底上再放白卡”，层级多但辨识度低。

### 交互与文案

- 「实例 / 服务器 / 房间」「总览 / 概览」「模组 / Mod / 内容」混用。
- 删除按钮实际只移除记录，却容易让人以为会删文件。
- 「换个房间」只做同路由跳转，旧房间状态可能还在。
- 崩溃诊断里“更换 Java”只弹提示，没有写入实例。
- 设置页无法切换服主 / 玩家模式。
- 部分长路径、长说明和操作组在窄窗口里会挤在一起。
- 资源列表只支持 Enter，不支持 Space，键盘操作不完整。

### 工程与可访问性

- 所有页面 eager import，首屏一次加载全部代码。
- 表单 label 与自定义控件的关联不可靠。
- 进度、日志、筛选状态缺少必要的可访问语义。
- 部分图标按钮没有稳定的可访问名称。
- 没有 `prefers-reduced-motion` 支持。
- 没有 404 兜底路由，未知地址会留下空主区。

## 4. 设计方向

### 4.1 核心概念：茶室工作台

保留 Geist 的清晰与克制，但不再是纯灰工具，而是加入一点“开服茶”自己的温度：

- 深色使用带绿意的暖黑，而不是纯黑。
- 浅色使用轻微米绿底，而不是冷白。
- 品牌色为低饱和茶绿，只用于当前位置、主操作和健康状态。
- 卡片和正文明确分层，减少无意义的嵌套和重复容器。
- 继续桌面优先，不为不存在的手机开服场景设计复杂触屏交互。

### 4.2 设计原则

1. **状态优先**：先回答“服务器现在怎么样”，再展示细节。
2. **下一步明确**：每个空状态都给出下一步动作，不做纯展示。
3. **降低解释成本**：技术信息保留，但配一句人能看懂的话。
4. **品牌克制**：茶绿只做点缀，不把所有按钮都染成品牌色。
5. **动效服务反馈**：按压、弹层和状态变化有反馈；控制台高频操作不堆动画。
6. **保留能力边界**：不改 `window.mcss` 契约、不弱化安全确认、不动配置迁移。

| 旧写法 | 新写法 |
| --- | --- |
| 实例 / 房间 / 服务器混用 | 服务器（仅房间码语境保留“房间”） |

| 启动中显示为运行中 | 启动中 / 运行中分开 |
| 重构版 | 已移除 |

### 8.2 文案基调

- 不卖萌，不喊口号，不用感叹号堆热情。
- 技术名词保留，但后面补一句人话解释。
- 错误说明“发生了什么、可以怎么办”，不只报错。
- 危险操作明确后果和边界。
- 空状态尽量给下一步，不只说“暂无数据”。

### 8.3 多语言

这轮没有引入 i18n 框架。原因是当前文案与业务状态强耦合，直接抽 key 会带来较大的行为风险。当前已完成中文术语统一和文案重写，后续如需英文版，建议单独做“文案资产化”阶段。

## 11. 刻意没做的事

这些不是遗漏，而是为了避免在这轮视觉升级里扩大风险：

- **没有推倒重写业务页面。** 保留现有 API、状态和数据结构。
- **没有删除任何安全确认。** 停服、恢复、UPnP、重置等危险操作仍然需要确认。
- **没有改变配置格式。** v28 配置、迁移和同步逻辑保持原样。
- **没有把桌面版改成移动端产品。** 仅保留窄窗口不挤爆的兜底。
- **没有引入 UI 框架或动画库。** 继续用现有 Tailwind、Radix、Lucide。
- **没有强行做完整 i18n。** 先把中文文案和术语打稳。
- **没有提交 Git。** 当前改动保持未提交，便于先实际体验。

## 12. 已知边界与下一阶段建议

### 仍存在的结构问题

1. **两套总览没有合并。** 全局总览和实例总览已经统一视觉语言，但仍是两套实现，长期存在继续漂移的风险。建议下一阶段抽成共享的服务器仪表盘组件。
2. **部分危险操作仍使用 `window.confirm`。** 与自绘 Dialog 的风格不统一，建议逐步替换。
3. **Mod 启停能力仍不完整。** 插件页已有启停，Mod 页只有绑定和安装，属于功能缺口，不是本轮视觉问题。
4. **实例核心切换仍不完整。** 设置里没有 `serverType` 控件，内容页已改成不误导的「服务器设置」，但真正换核心仍需后续产品设计。
5. **Web 首屏仍有体积提醒。** 页面已经拆分，初始 index 约 562 kB，gzip 约 181 kB；Vite 仍提示超过 500 kB，不阻塞构建。
6. **没有自动化视觉回归。** 本轮截图检查是人工完成，后续可加 Playwright 截图对比。

### 建议顺序

1. 合并两套总览，抽出共享状态卡与指标组件。
2. 完整补 Mod 启停、核心切换等已有承诺的功能。
3. 统一危险确认弹窗，移除 `window.confirm`。
4. 建立英文文案资产，再做真正的多语言。
5. 增加关键页面的视觉回归与键盘路径测试。
6. 实际体验稳定后再提交 Git，并按功能拆成若干提交更利于回滚。

## 13. 结论

这轮升级解决的是“工具能不能让人愿意长期用”的问题，而不只是“看起来是否现代”。

视觉上，开服茶从一套通用灰黑工作台，变成了有自己温度和识别度的桌面产品；交互上，主要路径更清楚，空状态和危险操作更诚实；工程上，构建与测试通过，页面按需加载，原有业务契约没有被破坏。

下一步不宜继续堆视觉细节，而应先把仍然存在的功能缺口和重复结构收掉，再进入多语言与更完整的自动化验证。

## 14. 接手复核（鲸鲸，2026-10-31）

复核方式：`pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm build:web`，并在 Electron 里逐页截图（总览、全部服务器、实例总览、控制台、设置、加入、联机、我的服务器、客户端），深浅两套主题都看了一遍。

结论：方向成立，业务链路没有断，测试与构建都过。补了三处细节：

1. **跳过导航链接会把人送回首页。** 原来写成 `<a href="#main-content">`，HashRouter 会把 `#main-content` 当成路由 `/main-content`，命中 404 兜底后 `Navigate` 回 `/`。改成按钮 + `main.focus()`。
2. **实例总览左栏被拉出大片空白。** 两栏 grid 默认 `items-stretch`，左栏「邀请朋友来玩」内容少，却被拉到和右栏「服务器信息」同高。加 `items-start`，让卡片按内容收缩。
3. **没生成邀请码时也报“旧链接 Mod 不全”。** `stale` 只看 localStorage 里的旧指纹，不管当前有没有 `code`。改成 `stale && code` 才提示。

顺手把首次模式选择里的蓝色链接和灰色图标容器统一成茶绿，避免第一屏出现第三套强调色。

另外补了一个**路由切换后主滚动区回顶**的兜底：从设置页滚到底再点「总览」，新页面会停在半截。这个不是布局 bug（弹窗后手动滚动是正常行为），只是切页时的默认体验。

界面上仍值得下一轮处理：两套总览合并、`window.confirm` 全部换自绘确认、Mod 启停与核心切换、关键页面的视觉回归。这些不影响本轮交付。
