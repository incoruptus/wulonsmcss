## 1. 结论

v27 的功能与视觉已经稳定，v28 不应该再堆功能，而是把「能发布、能维护、能翻译」这三件事补齐：

1. **能发布**：仓库、作者主页、项目主页、agent 下载地址目前都是空占位；CI 与部署脚本还没有落地。
2. **能维护**：511 条文案优化稿需要回填；19 处 JSX/模板片段要合并后再改；长文本 5 条要单独处理。
3. **能翻译**：i18n 还没有基础设施；现阶段所有文案都是中文硬编码，直接做英文会变成第二套硬编码。

## 4. 双语 i18n（P1）

现状：**内核 + Provider 已落地，页面尚未迁移**（按“先只搭框架”的决定）。

建议方案（不引第三方依赖）：

- `I18nProvider` + `useI18n()`；`t(key, fallback, vars?)` 已挂在根节点。
- 语义 key（`nav.overview`、`settings.appearance.title`），不用中文当 key。
- 词典分 `zh.ts` / `en.ts`，按命名空间拆文件；缺 key 时回退中文并在开发态 warn。
- 先迁外壳 + 导航 + 设置 + 总览，再按页面推进；错误文案（Electron/Rust）单独一层映射。
- 设置页加「语言：中文 / English」；切换即时生效，不重载整页。
- 翻译覆盖度后续加脚本统计；本期只落框架，不要求覆盖率。

**不建议**把中文原文当 key：文案一改，英文词典全部失配；也不建议现在直接上 `i18next`，当前体量用 200 行以内的 Provider 就够，后续要换再换。
